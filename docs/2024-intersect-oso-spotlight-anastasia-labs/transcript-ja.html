このページについて。Intersect の Open Source Office のチャンネル（「Open Source Office at Intersect MBO」、@osointersectmbo）で公開されている動画なので、発言者は実名のままです。Tex は Open Source Office の司会（姓は動画に出ません）、Philip DiSarro は Anastasia Labs の CEO・創業者で、冒頭で本人が名乗ります。

原本は時刻も話者名もない素の文字起こしで、短い段落に分かれています。問いと答えが交互に来るインタビューなので割り当ては明確で、末尾の「よい一日を」だけ (推定) を付けました。Philip DiSarro の長い答えは話題の切れ目でターンを分け、英語全文と同じ分割にしています。原本に時刻がないので、このページには .turn-time がありません。

固有名詞の誤変換はありませんでした。Charli3、Minswap、SundaeSwap、Meld、Polygon、Optimism、Arbitrum、zkSync、Hydra はいずれも各プロジェクトの綴りどおりです。訳では口語のフィラーを落としています。

公開日は「2024 年」までしか分かっていません。月日はこの環境から YouTube のページで確認できず、要確認としています。

冒頭 — 自己紹介

Tex

皆さん、こんにちは。Open Source Office の Tex です。今日はまた組織スポットライトの回で、Anastasia Labs の Philip に来てもらいました。何をしているところなのか、もう少し話してもらいます。Philip、簡単に自己紹介をお願いできますか。

Philip DiSarro

はい。Philip DiSarro です。Anastasia Labs の CEO で創業者です。Anastasia Labs は、Cardano のスマートコントラクトと dApp のプロトコル開発を専門にする研究開発会社です。

Tex

すばらしい。ありがとうございます。いくつか質問をして、はっきりさせていきましょう。Cardano のエコシステムの中で、Anastasia Labs の主な使命はどういうものか、概要を話してもらえますか。

使命 — オープンソースの本番コード

Philip DiSarro

はい。私が Anastasia Labs を作ったのは、オープンソースで本番品質の dApp プロトコルのコードを、エコシステム全体でもっと手に入るようにする、それだけが目的でした。Cardano の大きな痛点のひとつが、そこから組み立てられるオープンソースの本番コードベースがないことでした。これはエコシステムに、お金と時間という目に見える形で実害を与えます。

Philip DiSarro

たとえば、新しいチームがどのプロトコルの上に作るかを決めるとします。選択肢が 2 つあって、ひとつは、すでにある成果物から始めて、自分たちの事業に固有のロジックを足し、機能開発と事業要件に集中できる道。もうひとつは、ゼロから始めて、インフラも dApp の土台も含めて全部を自分で作らなければならず、引き出せるものも乗れるものも何もない道。後者だと、ずっと魅力が薄くなります。

Philip DiSarro

ですから Anastasia Labs を立ち上げたとき、主な焦点は、オープンソースのスマートコントラクトと、端から端までそろった dApp を大量に出すことでした。ひとつには、新しく入ってくるプロジェクトが、設計パターンや本番アプリケーションの作り方を学ぶ参考資料として使えるように。もうひとつには、全部をゼロから作るのではなく、この既存の成果物の上に作れるように。

Philip DiSarro

そうしないと、重複した支出がたくさん生まれます。よく似たプロダクトを作ろうとしているアプリが 10 あれば、そのプロダクトの土台、中核のインフラの大半は同じです。上のほうで少し違いが出ます。あるものにはほかにない機能がある、というように。ただ、そこに行くまでに、全員が土台を作らなければならない。そこに注ぎ込んだ時間とお金は重複して使われたもので、機能開発にも、開発者の増員にも、セキュリティにも回せたはずのものです。

セキュリティ — 形式検証のツールキット

Tex

まったくそのとおりです。とても重要なことですね。最後のほうで触れたことが次の質問につながります。dApp と、失礼、スマートコントラクトの話で、Cardano のブロックチェーンとどう結びつくかは分かりました。では、作っているものの独自の特徴で、データの信頼性とセキュリティを高めるものは何でしょうか。

Philip DiSarro

セキュリティについては、監査のためのツールを、作ったものも作っているものも、いくつも持っています。たとえば、旗艦となるツールのリリースのひとつが、Cardano のスマートコントラクト向けの形式検証ツールキットです。Cardano と、Cardano の上でアプリケーションを作ることの大きな利点のひとつは、使う言語とツールが形式検証にとても向いていることです。形式検証とは、プログラムの正しさを数学的に証明する仕組みです。これは、金融のオペレーティングシステムのようなミッションクリティカルなアプリケーション、つまり貸付のプラットフォームや取引のプラットフォームなどを作るときに本当に大事です。結局、非カストディアルのプラットフォームを作るなら、アプリケーションのロジックは隙がないものでなければならない。問題があれば利用者の資金が失われるし、悪意のある者に盗まれることもある。だからこそエコシステムは、形式手法を使えるようにする設計をこれほど重視したのです。

Philip DiSarro

ただ、これまでは、それを普通の開発者の手に届くものにしたツールキットは出ていませんでした。形式手法はとても参入の難しい分野です。やっている人はたいてい形式手法の修士号か博士号を持っていて、とくに Cardano の小さなチームにとっては、そういう人を雇うのも、自分たちでプロトコルの正しさを形式的に証明できるようになるのも、とても高くつきます。私たちが出したのは、基本的にその参入障壁を下げるツールキットで、標準的な開発者なら誰でも、ドキュメントをさっと読んで、自分の dApp の正しさについての証明を書き始められるはずのものです。

用途 — 差し込めば使えるコントラクト

Tex

すばらしい。では、Cardano のエコシステムでの Anastasia Labs のプロダクトの主な用途はどういうものでしょうか。

Philip DiSarro

私たちがやってきたことのよいところは、Cardano で何を作っていても、すでに作ってあるオープンソースのものを使えば何らかの便益が得られるはずだ、という点です。既存の成果物はどれも無料で、すべてオープンソースです。

Philip DiSarro

目的は、エコシステムの重複した支出を減らすことです。たとえば Cardano で新しいプロジェクトを始めるとして、とてもよくあるのが、トークンを出して、チーム向けのベスティング（段階的な付与）のスケジュールを持ちたい、という場合です。これには厄介なことが多い。全員がベスティングのスケジュールを守ると、どう信じるのか。全員がきちんと受け取り、トークンが投げ売りされないと、どう信じるのか。資金を誰が預かるのか。そこで、スマートコントラクトでベスティングをやるのがとても一般的です。ということは、開発者を雇ってそのスマートコントラクトを作ることになり、本来のプラットフォームを作る代わりに、チームのトークンのベスティングのインフラのようなものを作っている。筋が通りません。そうする代わりに、私たちの既存のベスティングの「差し込めばすぐ使える（plug and play）」ソリューションを使えます。実際、Charli3 などエコシステムの大きなプロジェクトがそうしていて、自分たちで作って監査するのに比べて数万ドル節約できました。ほかにも同じようなアプリケーションがたくさんあります。私たちの GitHub を見ると、ベスティングがひとつ、シンプルなピアツーピアの取引がもうひとつ。

Philip DiSarro

人はよく、標準的でない資産、たとえば NFT などを取引したいとか、いくつかの NFT をほかの NFT や資産と交換するような変わった取引をしたいと思いますが、これは DEX ではできません。そこで人がやるのが、仲介者を置くことです。自分の資産をその仲介者に送って、仲介者が 2 者の間の取引を取り次ぐ。これは本当に危険で、そういうやり方は詐欺を大量に生みます。ですから、この差し込めば使えるソリューションを使って、どんなウェブサイトでもスワップを支えられる、というのがもうひとつです。サブスクリプションの支払いもあります。ステーキングもあります。

Philip DiSarro

エコシステムの多くのプロジェクトが、報酬や投票権などのために何かにステークできるトークンを持ちたがります。それも私たちの差し込めば使えるソリューションのひとつです。これらすべてのよいところは、自分のアプリケーションに組み込むのに Cardano について何も知らなくてよいことです。たとえばコーヒーショップでも、世界のどんなウェブアプリケーションでも、ブロックチェーンのことは何も知らないけれど、「ADA での支払いを受け付けたいかも」「ADA のサブスクリプションを許したい」「コーヒーを追跡する NFT の機能を持ちたい」と思ったら、私たちの GitHub にある差し込めば使えるソリューションに行って、Cardano も UTXO も何も理解しないまま、自分のウェブサイトに差し込めます。

採用例 — 設計パターンのリポジトリ

Tex

とても効率的で、面白そうですね。いや、面白そうで、とても効率的、と言うべきでした。あなたのツールを取り入れた組織やプロジェクトがいくつかある、と言っていましたね。重要な成功例、あるいはいちばん目立つものとして挙げられるものが 1 つか 2 つありますか。

Philip DiSarro

はい。ベスティングは確実に、エコシステムのたくさんのチームに取り入れられています。実際、この時点ではすべてのチームを把握しているわけでもありません。人が私たちのものを使っていると分かって驚くことが、しばしばあります。

Philip DiSarro

いちばん影響が大きかったリリースは、おそらく設計パターンのリポジトリだと思います。開発者向けに、最先端の dApp の設計パターンを詳しく説明したものです。Cardano へのオンボーディングはとても大変で、ほかの分野で、それがいちばん複雑な分野であっても、きわめて有能なプログラマーであったとしても、Cardano のエコシステムに入ってくるのはとても難しい。ベストプラクティスを学ぶには、大量のオープンソースの成果物が手に入る必要があるからです。しかも、全員が違うツールを使っている分断されたエコシステムでは、技法を学ぶだけでも相当に込み入ったものになります。その技法はとても非標準的で、たとえば Cardano のベストプラクティスは、ほかのどこのベストプラクティスとも大きく違います。そこで私たちは、この設計パターンのリポジトリを出して、最先端の設計パターンをすべて詳しく説明しました。ほかのチームから私にこれを教えてくれることが絶えずあって、「はい、それを書いたのは私です」となる。それが見られたのは本当にうれしいことでした。

Philip DiSarro

大きなプロジェクトで開発者をオンボーディングするときに、どのチームもこれを見せるのが、もうほぼ標準になったと思います。実際、IOG でも、これがスタッフにトピックを説明するために使われ、共有されているのを見ました。Minswap でも、SundaeSwap でも、Cardano の主要なアプリのほとんどで共有されているのを見ています。

これから — レイヤー 2 と Midgard

Tex

ええ、すばらしい。共有してくれてありがとうございます。それはまさに、教育、あるいは教育を助ける資産がとてもとても重要だ、という点を示していると思います。おっしゃったように、ここでオンボーディングされて、オープンソースの成果物にアクセスできるようにするために。オープンソースの成果物の中に教育がたくさんなければ、プロセスをさらに複雑にしてしまいますから。あといくつか質問があります。難しいものではありません。Anastasia Labs の今後の計画、開発や新機能、新しいプロダクトについて、どうお考えですか。

Philip DiSarro

もちろん、オープンソースの公共のユーティリティのスマートコントラクトを引き続き出し、ほかの開発者がその上に作ったり引き出したりできる、大きく広がり続ける成果物の集まりを作って、オンボーディングのプロセスを楽にしていきます。設計パターンのリポジトリも引き続き拡充して、最新に保ち、新しい開発者のオンボーディングを助けます。

Philip DiSarro

それと、会社として大きく変わったことのひとつがあります。私たちが最初に入ってきたときの dApp エコシステムと、今の状況について振り返りをしました。人が学べるオープンソースのコードの量は大幅に増えて、今では「Cardano で開発するのは難しい、オンボーディングが難しい」と主張することがそれほど説得力を持たなくなった。人が学べるオープンソースのコードの量が飛躍的に増えたので、Cardano の最良のアプリケーションを見て、コードを見て、どう作られているかを見て、比較的早く学べます。これにはとても満足していて、では次の一歩は何か、と考えました。

Philip DiSarro

ほかのエコシステム、たとえば Ethereum を見ると、いちばん大きな改善、経済成長のいちばん大きな推進力は、コアプロトコルの変更ではありませんでした。実際、過去 3〜4 年の Ethereum のコアプロトコルの変更は比較的小さく、あまり好評でもなかった。成長のいちばん大きな触媒は、独立したチームがレイヤー 2 のソリューションを作ったことです。たとえば Polygon、Optimism、Arbitrum、zkSync。これらすべてが、Ethereum のレイヤー 1 に大量の経済成長をもたらしました。どれもセキュリティは Ethereum に頼りつつ、機能では独自の違いを出せる。これはブロックチェーンにとって重要です。ひとつにはトリレンマがあって、ひとつのブロックチェーンがすべてのアプリケーションに合うことはできないからです。

Philip DiSarro

ブロックチェーンを作るときには必ずトレードオフが要ります。セキュリティ、スケーラビリティ、分散性。あるアプリケーションはセキュリティを本当に重視し、別のアプリケーションはスケーラビリティを本当に重視する。ということは、ひとつのブロックチェーンが、その 2 つのアプリケーションにとって最良の場所にはなれない。レイヤー 2 のよいところは、レイヤー 1 を離れずに、アプリケーションが必要とする機能を持つソリューションを作れることです。たとえば、きわめて高いスループットのブロックチェーンが要る人がいれば、今のところ Cardano はその用途にあまり向いていないかもしれない。けれども Hydra やほかのレイヤー 2 のソリューションなら、エコシステムを離れずにそれを作れます。

Philip DiSarro

今作っているのが、旗艦プロダクトの Midgard です。Cardano 向けの optimistic rollup で、レイヤー 2 を作るためのフレームワークです。これを Cardano の「唯一のレイヤー 2」にしたいわけではなく、Optimism のようなものにしたい。つまり、人が自分のアプリケーションのために、あるいは自分の要件に合わせてレイヤー 2 を作るのに使える SDK です。たとえば、連合型（federated）のネットワークを持ちたい、サプライチェーンの追跡のレイヤー 2 を持ちたい、ゲームのレイヤー 2 を持ちたい。そういうものがすべて Midgard で作れます。Midgard 自体も、もちろん単独のレイヤー 2 として存在します。

Philip DiSarro

ただ、これはエコシステムの成長の大きな触媒になると考えています。突然、Cardano に経済的なセキュリティを頼る、たくさんの違ったレイヤー 2 が現れることになるからです。つまり、Cardano の上に作りたくないかもしれないアプリケーションにレイヤー 2 を売り込めれば――たとえば Meld は、清算とスループットについての懸念からエコシステムを去りましたが――レイヤー 2 の上に作ってもらえれば、実質的にその経済活動がレイヤー 1 に乗ります。レイヤー 2 は Cardano に頼り、セキュリティの対価を Cardano に払うからです。これは成長の大きな触媒になると考えていて、とても楽しみにしています。

コミュニティ、締め

Tex

楽しみなことがたくさん進んでいますね。それでも、やることが多すぎるとは言いにくい、よい位置にまだいると思います。最後に締めとして、Anastasia Labs はコミュニティとどう関わっていますか。コミュニティが関わる方法にはどんなものがありますか。

Philip DiSarro

Discord に入ってもらえますし、私には Discord、Twitter、メールのどれでも連絡できます。関わるいちばんよい方法は技術的な質問です。それを手伝うために私たちはいるのですから。オープンソースのリポジトリの使い方や、出しているツールについての質問があれば、何でも。また、エコシステムに足りていないと感じるもの、たとえば「XYZ のオープンソースのソリューションがあればいいのに、存在しない」というものがあれば、ぜひ連絡してください。十分な需要があれば、間違いなく私たちが出すものになります。

Tex

ありがとうございます。あなたと Discord サーバーの連絡先を用意して、この動画の説明欄に必ず付けます。見てくれている皆さん、いいね、コメント、チャンネル登録を忘れずに。様子を教えてください。それと、Intersect のメンバーになることでも Cardano のエコシステムに関われますので、お忘れなく。ありがとうございました。また次回お会いしましょう。

Philip DiSarro (推定)

それでは、よい一日を。
